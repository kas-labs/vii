# Historical Regression Matrix — Form P1k Browser & Accessibility Acceptance

This document records the historical regressions, failure modes, production owners, acceptance invariants, and real-browser test locations transferred from Form Research (F1–F10) and production slices (P1g–P1j) to the **P1k Browser Acceptance Gate**.

| ID | Name | Origin | Historical Failure Mode | Production Owner | Browser Spec & Test | Acceptance Invariant |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **P1K-H01** | Single-commit text edit | P1i / F7 | Dual `input` + `change` registration or redundant commits per single keystroke caused duplicate validation runs and feedback loops. | `packages/form/src/adapters/vanilla/bind-field.ts` | `vanilla-field.spec.ts`<br>`"commits exactly once per text keystroke without duplicate change validation"` | Exactly 1 input event, 1 raw commit, and 1 validation invocation per keystroke. |
| **P1K-H02** | Parsed raw intermediate input (no snap-back) | F3 / P1e / P1i | In parser-backed inputs (e.g. `Field<number, string>`), typing intermediate invalid characters (e.g. `"-"` or `"1."`) caused premature formatting or snap-back to the prior valid value, erasing user input. | `packages/form/src/adapters/vanilla/bind-field.ts`<br>`packages/form/src/core/field.ts` | `parser-raw.spec.ts`<br>`"preserves intermediate invalid raw presentation without snap-back"` | Intermediate raw string is preserved in DOM `value` and `field.rawValue`; `field.value` retains last-good parsed value; `field.parseStatus === "invalid"`. Completing valid number updates domain value. |
| **P1K-H03** | `aria-invalid` application baseline restoration | P1i / F8 | Binding to an element with pre-existing `aria-invalid="grammar"` overwrote the attribute on valid state or removed it on disposal, destroying application-owned a11y semantics. | `packages/form/src/adapters/vanilla/a11y.ts` | `vanilla-a11y.spec.ts`<br>`"preserves and restores pre-existing aria-invalid baseline"` | Element with `aria-invalid="grammar"` transitions to `"true"` when invalid, restores to `"grammar"` when valid, and restores to `"grammar"` on disposal. |
| **P1K-H04** | Overlapping `aria-invalid` bindings | P1i / F8 | When multiple bindings share a single DOM element, disposing one binding cleared `aria-invalid` even if another binding was still invalid. | `packages/form/src/adapters/vanilla/a11y.ts` | `vanilla-a11y.spec.ts`<br>`"coordinates overlapping aria-invalid bindings with WeakMap ownership"` | If ANY active binding on an element is invalid, `aria-invalid="true"`. Disposing a valid binding leaves `"true"`. Disposing all bindings restores baseline. Works in forward and reverse disposal order. |
| **P1K-H05** | Safe issue-message textContent sink | F8 / F10 / P1i | Hostile strings in validation or server issues (e.g. `<img src=x onerror=...>`, `<script>`) evaluated as HTML if injected via `innerHTML`, causing DOM-based XSS. | `packages/form/src/adapters/vanilla/a11y.ts` (`renderSafeIssues`) | `safe-sink.spec.ts`<br>`"projects hostile issue messages strictly as textContent without HTML evaluation"` | Hostile payload renders strictly as textContent; 0 child HTML nodes created; 0 scripts or onerror handlers executed (`globalThis.__viiP1kXss` remains unset). |
| **P1K-H06** | Submit rejection containment | P1i / ARCH §16 | Submit action rejecting unexpectedly in a fire-and-forget DOM submit listener caused `unhandledrejection` on window or unintended browser navigation. | `packages/form/src/adapters/vanilla/bind-form.ts` | `vanilla-submit.spec.ts`<br>`"contains unexpected submit action rejection and routes to onSubmitException"` | Action rejection is caught and forwarded to `onSubmitException`; 0 `unhandledrejection` events emitted on window; browser navigation is prevented. |
| **P1K-H07** | Edit during submit validation cancels stale submission | P1g / F5 | Editing a bound input while async submit validation was pending allowed a fresh unvalidated value into the in-flight submission snapshot (Model A race). | `packages/form/src/core/form.ts` | `submit-lifecycle.spec.ts`<br>`"cancels stale submit when field is edited during async submit validation"` | In-flight submit validation detects mutation; submit action is NOT invoked with unvalidated fresh value; submission status transitions to `"cancelled"`. |
| **P1K-H08** | Edit during async field validation supersedes pending request | F4 / P1e | Slower earlier async validation request resolving after a faster later edit overwrote the fresh validation state with stale issues. | `packages/form/src/core/field.ts` | `async-cancellation.spec.ts`<br>`"supersedes pending async validation when fresh edit occurs"` | Earlier slow validation resolution is ignored; fresh edit state remains authoritative; no stale validation issue flashes in DOM. |
| **P1K-H09** | IME composition sequencing | ARCH §14.1 / F10 | Intermediate IME composition events triggered premature validation or parser formatting, corrupting multi-stage syllable input (Japanese, Korean, Chinese). | `packages/form/src/adapters/vanilla/bind-field.ts` | `ime.spec.ts`<br>`"handles Japanese / Korean / Chinese / parser-backed composition sequences without premature commits"` | Intermediate composition events (`isComposing: true`) suppress `setRawValue` commits and validation runs; exactly 1 raw commit and 1 validation run occur upon final composition completion (`isComposing: false`). Parsed inputs preserve intermediate DOM presentation without snap-back. |
| **P1K-H10** | Focus preservation across issue projection | F8 / ARCH §14.1 | Projecting validation error messages or updating `aria-describedby` caused the focused input to lose focus or reset cursor position. | `packages/form/src/adapters/vanilla/bind-field.ts`<br>`packages/form/src/adapters/vanilla/a11y.ts` | `focus.spec.ts`<br>`"preserves input focus when validation issues and ARIA attributes project"` | Focused input remains `document.activeElement` during and after validation issue projection. |
| **P1K-H11** | Localized server issue clearing on field edit | P1g / F5 | Editing one field cleared server issues globally across all fields, or editing an invalid field failed to clear its localized server issue and ARIA projection. | `packages/form/src/core/form.ts`<br>`packages/form/src/adapters/vanilla/bind-field.ts` | `historical-regressions.spec.ts`<br>`"clears localized server issue on edit while preserving sibling issues"` | Modifying Field A clears its server issue and `aria-invalid`; Field B retains its server issue, `aria-invalid="true"`, and error description. |
| **P1K-H12** | Route-style UI unbind during in-flight async work | ARCH §14.1 / F10 | Unmounting / disposing UI bindings while async validation or submission was pending caused stale DOM mutations, errors on detached nodes, or memory retention. | `packages/form/src/adapters/vanilla/bind-field.ts`<br>`packages/form/src/adapters/vanilla/bind-form.ts` | `lifecycle.spec.ts`<br>`"handles route teardown during active async validation without detached DOM mutation"` | Binding `dispose()` unregisters DOM listeners; resolving async work produces 0 errors and 0 mutations on detached nodes; canonical Form/Field state remains sound. |
| **P1K-H13** | Unsupported control fail-closed preflight | P1i | Binding unsupported elements (e.g. `<div>`, `<button>`) silently attached listeners or produced corrupt form state. | `packages/form/src/adapters/vanilla/control.ts` | `historical-regressions.spec.ts`<br>`"fails closed with TypeError on unsupported DOM elements"` | Preflight check throws deterministic `TypeError` before any DOM mutation or listener attachment. |
| **P1K-H14** | Deferred select-multiple preflight rejection | P1i | Binding `<select multiple>` was partially bound or silently dropped multiple selections. | `packages/form/src/adapters/vanilla/control.ts` | `historical-regressions.spec.ts`<br>`"rejects select-multiple with explicit TypeError"` | Preflight check throws deterministic `TypeError("Unsupported element: select-multiple is not supported in P1i")`. |
| **P1K-H15** | React real-browser lifecycle and freshness | P1h / F10 | React StrictMode double-mount or unmounting while async validation was in-flight dropped subscriptions or triggered memory leaks. | `packages/form/src/adapters/react/` | `react-lifecycle.spec.ts`<br>`"handles React 19 mount, edit, unmount during async validation, and remount"` | Clean subscription teardown on unmount; 0 memory leaks; 0 console errors/warnings; snapshot freshness preserved across remount. |
