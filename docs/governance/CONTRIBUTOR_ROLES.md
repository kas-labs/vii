# Contributor Roles

Vii uses an earned-responsibility model. Roles reflect demonstrated contribution and current maintenance capacity.

## Community participant

Participates in discussions, reports issues, tests releases, or provides feedback.

## Contributor

Has one or more accepted contributions such as documentation, tests, code, benchmarks, or RFC feedback.

## Regular contributor

Contributes consistently and demonstrates familiarity with Vii architecture, quality expectations, and review practices.

## Package collaborator

Helps maintain a defined package or area. May triage issues and review changes but does not independently authorize stable releases.

## Package owner

Accepts responsibility for a package's quality, compatibility, documentation, lifecycle, and security coordination.

## Maintainer

May approve and merge changes in assigned areas, participate in governance, and help operate releases.

## Project lead

Owns product direction, final roadmap prioritization, repository administration, and final decisions when consensus is unavailable.

## Role changes

Roles are granted based on evidence including:

- quality and consistency of contributions
- technical judgment
- respectful collaboration
- understanding of project boundaries
- reliability in review and maintenance
- security and privacy awareness

Roles may be reduced when a person no longer has maintenance capacity. This is an operational adjustment, not a punishment.

## Least privilege

Repository and publication permissions should match current responsibilities. Access should not be granted solely as recognition.
